# Парсер контрактов zakupki.gov.ru

Скрипт для сбора информации о государственных контрактах с сайта Единой информационной системы в сфере закупок (zakupki.gov.ru). Данные сохраняются в CSV и PostgreSQL.

## Возможности

- Парсинг контрактов по 50 на странице
- Извлечение информации о заказчике и поставщике
- Очистка данных (ИНН, КПП, телефон, email)
- Сохранение в CSV с последующей загрузкой в PostgreSQL
- Автоматическое обновление существующих записей

## Установка

### Требования

- Python 3.10+
- Docker и Docker Compose (для базы данных)
- PostgreSQL 15 (опционально, если не через Docker)

### Установка зависимостей

```bash
pip install -r requirements.txt
```

### Настройка базы данных

1. Запуск контейнера с PostgreSQL:

```bash
docker-compose up -d
```

2. Проверка работы контейнера:

```bash
docker ps | grep postgres
```

### Настройка конфигурации

Проверка настроек подключения к БД в файле `config.py`:

```python
DB_CONFIG = {
    'host': 'localhost',
    'port': 5432,
    'database': 'zakupki_db',
    'user': 'zakupki_user',
    'password': 'zakupki_pass'
}
```

## Запуск

### Парсинг контрактов

```bash
python main.py
```

Скрипт запросит ввести количество страниц (по 50 контрактов на странице). После выполнения появится два файла:

- `contracts_raw.csv` - сырые данные
- `contracts_clean.csv` - очищенные данные

### Заливка данных в PostgreSQL

```bash
python database.py
```


## Возможные ошибки и их решение

### 1. Ошибка 429 Too Many Requests

**Причина:** слишком частые запросы к сайту

**Решение:** увеличить задержки в `main.py`:

```python
time.sleep(1.5)   # между карточками
time.sleep(3)     # между страницами
```

### 2. Connection refused (порт 5432)

**Причина:** PostgreSQL не запущен

**Решение:**

```bash
docker-compose up -d
# или
docker start zakupki_postgres
```

### 3. password authentication failed

**Причина:** неверный пароль в `config.py`

**Решение:** проверить пароль в `DB_CONFIG` или сбросить пароль в PostgreSQL:

```bash
docker exec -it zakupki_postgres psql -U postgres -c "ALTER USER zakupki_user WITH PASSWORD 'zakupki_pass';"
```

### 4. Column "supplier_inn.1" does not exist

**Причина:** дублирующиеся колонки в CSV

**Решение:** удалить дубликаты:

```bash
python -c "
import pandas as pd
df = pd.read_csv('contracts_clean.csv')
df = df.loc[:, ~df.columns.duplicated()]
df.to_csv('contracts_clean.csv', index=False)
"
```

## Рекомендации

- Не ставить задержки меньше 1.5 секунд, так как сайт может забанить
- На парсинг 100 страниц (5000 контрактов) уходит около 2.5 часов
- При ошибках бана подождать 10-15 минут и продолжить

# Анализ по секторам

## Возможности

- Классификация заказчиков и поставщиков по разделам и группам ОКВЭД-2 на основе ключевых слов
- Формирование файла `contracts_with_sectors.csv` с разметкой по разделам и группам ОКВЭД для каждого контракта
- Агрегация контрактов в межсекторные потоки на двух уровнях детализации
- Построение интерактивного HTML-графа, где можно смотреть связи между секторами, их оборот и примеры контрактов
- Возможность раскрыть любой раздел до уровня конкретных групп ОКВЭД двойным кликом по узлу

## Используемые файлы

### 1. Правила классификации

`sector_rules.py` содержит три структуры данных: словарь разделов ОКВЭД-2 (`OKVED_SECTIONS`), список групп с ключевыми словами (`OKVED_GROUP_RULES`) и вспомогательные словари для быстрого доступа.

Классификация работает через подсчёт совпадений ключевых слов в нормализованном названии организации. Побеждает та группа, у которой совпадений больше.

### 2. Классификация контрактов

`sector_classifier.py` присваивает каждому контракту раздел и группу ОКВЭД для заказчика и поставщика.

Индивидуальные предприниматели определяются отдельно. Если название соответствует шаблону ФИО или содержит "индивидуальный предприниматель", присваивается специальный код `IP`.

Результатом работы становится файл `contracts_with_sectors.csv`, где к каждому контракту добавлены поля `customer_section`, `customer_group`, `supplier_section`, `supplier_group` и их текстовые названия.

### 3. Построение межсекторных потоков

`build_sector_flows.py` агрегирует размеченные контракты по парам секторов и формирует два файла:

- `sector_flows.csv` — потоки на уровне разделов ОКВЭД (`source`, `target`, `money_flow`)
- `sector_flows_groups.csv` — потоки на уровне групп с полными названиями

### 4. Визуализация графа

`web_graph.py` строит интерактивный граф по данным из обоих файлов потоков и `contracts_with_sectors.csv`.

В итоговом HTML-файле два режима работы: верхний уровень с разделами ОКВЭД и детальный уровень групп, который открывается двойным кликом по любому узлу. В боковой панели для каждого выбранного сектора отображается общий оборот, топ входящих и исходящих потоков и примеры реальных контрактов.

## Запуск

> Все скрипты запускать из папки `v1`, иначе они не найдут CSV-файлы рядом с собой.

### 1. Классификация контрактов по секторам

```bash
python sector_classifier.py
```

После выполнения формируется файл:
- `contracts_with_sectors.csv` — контракты с добавленными разделами и группами ОКВЭД

### 2. Построение агрегированных потоков

```bash
python build_sector_flows.py
```

После выполнения формируются файлы:
- `sector_flows.csv` — потоки между разделами ОКВЭД
- `sector_flows_groups.csv` — потоки между группами ОКВЭД

### 3. Построение интерактивного графа

```bash
python web_graph.py
```

После выполнения формируется `sector_graph.html`. Открыть его можно двойным кликом в проводнике или командой:

```bash
start sector_graph.html
```

## Логика обработки данных

1. Берутся очищенные контракты из `contracts_clean.csv` после основного этапа парсинга
2. Названия организаций нормализуются: нижний регистр, замена `ё` на `е`, удаление спецсимволов
3. Для каждого контракта определяется раздел и группа ОКВЭД заказчика и поставщика
4. Результат сохраняется в `contracts_with_sectors.csv`
5. Контракты группируются по парам разделов и по парам групп с суммированием `price`
6. На основе обоих уровней агрегации строится интерактивный граф
