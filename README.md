# Парсер контрактов zakupki.gov.ru

Скрипт для сбора информации о государственных контрактах с сайта Единой информационной системы в сфере закупок (zakupki.gov.ru). Данные сохраняются в CSV и PostgreSQL.

## Возможности

- Парсинг контрактов по 50 на странице
- Извлечение информации о заказчике и поставщике
- Очистка данных (ИНН, КПП, телефон, email)
- Сохранение в CSV с последующей загрузкой в PostgreSQL
- Автоматическое обновление существующих записей

## Установка

### Требования

- Python 3.10+
- Docker и Docker Compose (для базы данных)
- PostgreSQL 15 (опционально, если не через Docker)

### Установка зависимостей

```bash
pip install -r requirements.txt
```

### Настройка базы данных

1. Запуск контейнера с PostgreSQL:

```bash
docker-compose up -d
```

2. Проверка работы контейнера:

```bash
docker ps | grep postgres
```

### Настройка конфигурации

Проверка настроек подключения к БД в файле `config.py`:

```python
DB_CONFIG = {
    'host': 'localhost',
    'port': 5432,
    'database': 'zakupki_db',
    'user': 'zakupki_user',
    'password': 'zakupki_pass'
}
```

## Запуск

### Парсинг контрактов

```bash
python main.py
```

Скрипт запросит ввести количество страниц (по 50 контрактов на странице). После выполнения появится два файла:

- `contracts_raw.csv` - сырые данные
- `contracts_clean.csv` - очищенные данные

### Заливка данных в PostgreSQL

```bash
python database.py
```

## Возможные ошибки и их решение

### 1. Ошибка 429 Too Many Requests

**Причина:** слишком частые запросы к сайту

**Решение:** увеличить задержки в `main.py`:

```python
time.sleep(1.5)   # между карточками
time.sleep(3)     # между страницами
```

### 2. Connection refused (порт 5432)

**Причина:** PostgreSQL не запущен

**Решение:**

```bash
docker-compose up -d
# или
docker start zakupki_postgres
```

### 3. password authentication failed

**Причина:** неверный пароль в `config.py`

**Решение:** проверить пароль в `DB_CONFIG` или сбросить пароль в PostgreSQL:

```bash
docker exec -it zakupki_postgres psql -U postgres -c "ALTER USER zakupki_user WITH PASSWORD 'zakupki_pass';"
```

### 4. Column "supplier_inn.1" does not exist

**Причина:** дублирующиеся колонки в CSV

**Решение:** удалить дубликаты:

```bash
python -c "
import pandas as pd
df = pd.read_csv('contracts_clean.csv')
df = df.loc[:, ~df.columns.duplicated()]
df.to_csv('contracts_clean.csv', index=False)
"
```

## Рекомендации

- Не ставить задержки меньше 1.5 секунд, так как сайт может забанить
- На парсинг 100 страниц (5000 контрактов) уходит около 2.5 часов
- При ошибках бана подождать 10-15 минут и продолжить

# Анализ по секторам

## Возможности

- Классификация заказчиков и поставщиков по секторам на основе правил и ключевых слов
- Формирование файла `contracts_with_sectors.csv` с разметкой `customer_sector` и `supplier_sector` для каждого контракта
- Агрегация контрактов в межсекторные потоки с итоговым файлом `sector_flows.csv`, содержащим `source`, `target`, `money_flow`
- Построение интерактивного HTML-графа, где можно смотреть связи между секторами, их оборот и примеры контрактов
- Подготовка структуры данных для дальнейшего анализа сети закупок

## Используемые файлы

### 1. Правила классификации

`sector_rules.py` содержит набор правил, по которым организации относятся к секторам.

В этих правилах задаются ключевые слова, шаблоны и логика сопоставления организаций с категориями вроде `government`, `healthcare`, `education`, `construction`, `business_other`, `individual_entrepreneur` и другими.

### 2. Классификация контрактов

`sector_classifier.py` отвечает за присвоение сектора заказчику и поставщику в каждом контракте.

Результатом работы становится файл `contracts_with_sectors.csv`, где к исходным данным о контракте добавлены поля `customer_sector` и `supplier_sector`.

### 3. Построение межсекторных потоков

`build_sector_flows.py` агрегирует размеченные контракты по парам секторов.

На выходе получается файл `sector_flows.csv`, в котором каждая строка показывает суммарный денежный поток между сектором заказчика (`source`) и сектором поставщика (`target`).

### 4. Визуализация графа

`web_graph.py` строит интерактивный граф по данным `sector_flows.csv` и `contracts_with_sectors.csv`.

В итоговом HTML-файле отображаются сектора, связи между ними, общий оборот по узлам, крупнейшие входящие и исходящие потоки, а также примеры контрактов для выбранной отрасли.

## Запуск

### 1. Классификация контрактов по секторам

```bash
python sector_classifier.py
```

После выполнения формируется файл:

- `contracts_with_sectors.csv` — контракты с добавленными секторами заказчика и поставщика

### 2. Построение агрегированных потоков

```bash
python build_sector_flows.py
```

После выполнения формируется файл:

- `sector_flows.csv` — агрегированные денежные потоки между секторами

### 3. Построение интерактивного графа

```bash
python web_graph.py
```

После выполнения формируется HTML-файл с визуализацией межсекторного графа.

## Логика обработки данных

Обработка данных выполняется в несколько этапов:

1. Берутся очищенные контракты после основного этапа парсинга.
2. Для каждого контракта определяется сектор заказчика и сектор поставщика.
3. Полученные данные сохраняются в `contracts_with_sectors.csv`.
4. Далее контракты группируются по парам `customer_sector` и `supplier_sector` с суммированием `price`.
5. Результат сохраняется в `sector_flows.csv`.
6. На основе этих файлов строится интерактивный граф для анализа связей между секторами.

## Структура файлов отраслевого анализа

```bash
v1/
├── sector_rules.py            # Правила и словари для отнесения организаций к секторам
├── sector_classifier.py       # Классификация заказчиков и поставщиков по секторам
├── build_sector_flows.py      # Агрегация контрактов в межсекторные денежные потоки
├── web_graph.py               # Построение интерактивного HTML-графа
├── contracts_with_sectors.csv # Контракты с секторами заказчика и поставщика
└── sector_flows.csv           # Сводные потоки денег между секторами
```

## Возможные ошибки и их решение

### 1. Организация попадает не в тот сектор

**Причина:** правило классификации в `sector_rules.py` слишком общее или не учитывает нужное ключевое слово.

**Решение:** проверить словари и шаблоны в `sector_rules.py`, затем повторно запустить:

```bash
python sector_classifier.py
```

### 2. В `sector_flows.csv` мало связей

**Причина:** не все организации были корректно классифицированы, либо часть данных отсутствует после очистки.

**Решение:** проверить, что в `contracts_with_sectors.csv` заполнены `customer_sector` и `supplier_sector`, а также что значения `price` корректно читаются и агрегируются.

### 3. HTML-граф не открывается или отображается некорректно

**Причина:** отсутствуют входные CSV-файлы или не установлены зависимости для визуализации графа.

**Решение:** убедиться, что перед запуском `web_graph.py` уже созданы `contracts_with_sectors.csv` и `sector_flows.csv`, а также установлены `pandas`, `networkx` и `pyvis`.

## Рекомендации

- Сначала всегда запускать классификацию, потом агрегацию потоков, и только после этого строить граф
- После изменения правил в `sector_rules.py` нужно заново пересобрать и `contracts_with_sectors.csv`, и `sector_flows.csv`
- Для проверки качества классификации удобно смотреть несколько строк из `contracts_with_sectors.csv` вручную и сравнивать их с итоговыми потоками в `sector_flows.csv`"
